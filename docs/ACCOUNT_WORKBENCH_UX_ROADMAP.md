# 账号管理工作台 UI/UX 升级清单

## 重新定义信息架构
- 「总览」：仅聚合关键计数、资源准备度、异常账号和近期记录；不展示明文账号密码或支付数据。
- 「创建与记录」：集中批量生成、选择资源、结果导出、筛选/状态更新。
- 「资源库」：邮箱、代理、支付令牌、营业执照；默认隐藏秘密，资源分配状态可见。
- 「团队管理」（待后端 RBAC 完成）：成员邀请、权限管理、账号归属审核；不提供查询其他成员资料的入口。
- 「系统工具」：备份、恢复、导出配置、健康状态；生产可审计、角色授权。

## 本次小步 UI 改动
- 新增「运营总览」导航页和最近账号、资源准备度快捷入口，保留原有创建表单。
- 导航增加 `aria-current`；资源库搜索/状态按资源类别分别记忆。
- 记录及资源页面增加清除筛选交互，减少跨页面筛选残留导致的误判。
- 对资源不足做提前说明，不假装当前服务端已经启用全团队共享配额。
- 业务页面使用业务字段描述，不把“登录用户数”当成全团队资源总数。

## 后续依赖后端的设计
- 加入团队身份与个人空间状态、**仅本人数据的全局搜索**、用户头像菜单、待处理通知。
- 我的记录视图按国家、产品、创建时间和状态筛选；仅管理员可查看脱敏聚合数据，不得浏览他人记录。
- 批量创建改为 3 步向导：填写 → 资源与冲突预览 → 确认 → 显示实际创建结果。
- 删除/敏感导出二次确认并记录审计；失败要有可重试但不重复提交的幂等流程。
- 禁止客户端直接将 `state.user.role` 作为唯一权限来源；后端必须逐请求鉴权。
- 审计列表支持操作者、时间、实体、动作筛选，不记录敏感字段。
- 响应式布局以桌面端密集表格为主，小屏用抽屉与卡片行；键盘/焦点可完整操作。

## 发布条件
始终保持“个人明细隔离 + 团队文件去重”；只有具备合法管理员权限才能访问脱敏的团队级统计，不将其他成员的资料作为可浏览资源库。
