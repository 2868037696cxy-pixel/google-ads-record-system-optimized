# Ads Workbench · UI/UX 设计规范（桌面产品）

> 2026-10-21 | 本规范约束网页与 Windows Electron 工作台。采用统一的浅色玻璃视觉，优先服务高频数据核对、录入、筛选与风险确认。

## 方法论来源与适配范围

- [Taste Skill / redesign-existing-projects](https://github.com/Leonxlnx/taste-skill)：先审计再改造，避免模板化视觉与相同卡片重复。
- [Impeccable](https://github.com/pbakaus/impeccable)：使用 critique → typeset → layout → audit → polish 的评审顺序。
- [shadcn/ui](https://github.com/shadcn-ui/ui)：借鉴控件 anatomy、状态与可访问性。不引入 React、Tailwind 或 shadcn/ui 运行时：当前代码是 Electron + 原生 HTML/CSS/JS；强迁移会增加回归与维护成本。

## 发现的结构性问题

1. `styles.css` 默认正文 13.5px，标签 10–11px，表单与表格长时间使用难读。
2. 侧栏同时承担主导航、敏感解锁、连接、备份、恢复、审计、改密、退出，信息层级混乱。高风险动作不应与主导航同级强调。
3. 荧光绿、辐射辉光、渐变、噪点和卡片嵌套争夺注意；不适合高频管理工作。
4. 录入、搜索、筛选、分页和状态控件高度不统一，部分按钮的命中面积过小。
5. 桌面多列横向表格没有明确的密度标准，冻结列、滚动与行状态要持续检查。
6. 页面引导文案和小标签字号偏小、低优先级说明过多，有效工作区被装饰挤压。

## 视觉与排版标准

| 范畴 | 标准 |
|---|---|
| 正文 | 14px / 1.55；不以 11px 作为功能性文本常态 |
| 页面主标题 | 27px / 1.28，字重 600 |
| 面板标题 | 15px / 1.5，字重 600–650 |
| 输入标签 | 13px、字重 600，可读颜色；必填和错误提示显式表达 |
| 次级说明 | 12–13px；不使用低对比度幽灵色承担关键业务信息 |
| 数字 | tabular-nums；仅编号、时间、统计需要等宽处理 |
| 控件高度 | 普通输入/按钮 40px；小按钮 ≥36px；侧栏导航 ≥42px |
| 间距节奏 | 4/8/12/16/20/24/32px；表单字段间 16–18px |
| 页面边距 | 标准桌面 28px 上下、20–44px 水平；窗口变窄递减 |
| 状态 | 正常/异常/停用不能只靠颜色区分，必须保留文字 |
| 主题 | 浅银白玻璃；仅侧栏、面板及遮罩使用有限模糊，数据和冻结表头使用实色底 |
| 动效 | 100–220ms，仅响应状态变化；遵循 prefers-reduced-motion |

所有新控件使用 `public/design-tokens.css` 中的变量。级联按 `legacy → tokens → foundations → components` 显式分层；新增原生控件与状态在 `ui-components.css` / `ui-components.js` 中复用。具体组件契约见 [UI_COMPONENTS.md](UI_COMPONENTS.md)。不要继续追加多个互相覆盖的“最后一行 CSS 修复块”。

## 行为契约

### 记录列表
- 当前页数据源为后端真实分页，默认 50 条。
- 搜索输入保留焦点和光标，250ms 防抖；过期成功/失败响应均不能覆盖新结果。
- 全选仅当前页。跨页选择必须保留数量并在删除/导出对话框明确提示实际操作范围。
- 冻结复选框与指纹列；水平滚动后这两列仍可阅读。不能用截断省略关键指纹。
- 资源占用状态来自服务器对本人**全部记录**的计数，不得复用当前页记录判断。

### 表单
- 提交时禁用重复点击、保留用户已填内容。
- 后台已成功、刷新失败时必须提示“已保存/删除，但刷新失败”，不能让用户误操作第二次。
- 校验错误应就近呈现且字段恢复焦点；严禁静默转换非法状态或类型。

### 弹窗与破坏性操作
- 明确标题、影响范围、主要操作与取消；危险操作不放首要视觉位。
- ESC 取消草稿、关闭不保存；焦点进入弹窗且关闭后恢复到触发按钮。
- 长内容弹窗仅正文滚动，操作区保持可见；不得让“确认”挤出窗口。
- 需要二次解锁的数据导出不能因视觉改造放松授权边界。

### 键盘、适配与无障碍
- 真实 Windows 端 100%/125%/150% DPI 验收。
- 至少测试 1280×720、1440×900、1920×1080 三类窗口；窄宽优先保持最小可用交互，表格水平滚动而不是挤窄列。
- 所有按钮有可见 focus，输入有可识别 label，图标不得成为唯一可理解名称。
- 不依赖颜色或 hover 才能找到操作。禁用态保留可理解的原因。
- 避免整个屏幕滚动和内层滚动互相抢滚轮，侧栏导航与账户操作可分别到达。

## 当前改造边界和下一阶段

**已实施的基础：** 统一 UI 字号、控制高度、间距、数据面板层级、统计卡、表格、弹窗、响应式密度与 reduced-motion 支持；每个用户独立的“舒适／紧凑”记录表密度偏好只影响显示。后续颜色和材质以文末浅色规范为准。

**下阶段尚须可视化验收：**
1. 实际 Electron 截图对比（登录、运营总览、记录、创建、4 资源库、导入/编辑/恢复弹窗）。
2. 侧栏信息架构拆分为“导航 / 账号 / 设置”，但迁移之前必须同时更新自动化测试依赖的操作入口。
3. 表格列宽策略（不同国家的长公司名/多语言）、列显隐、水平滚动与排序反馈。
4. 空状态、错误态、加载骨架、批量操作、危险确认交互和键盘焦点循环。
5. Windows 125%/150% 缩放、窄窗口与弱网/慢端机真实验收。
6. CSS 层整理，消除历史样式重复声明和颜色硬编码；UI视觉测试与截图基线入 CI。

### 本轮继续落地（2026-10-20）

- 提取字体、颜色、间距、尺寸、焦点和动效令牌；历史样式降为 legacy 层，合并窄桌面冲突规则。
- 复用公共按钮、空状态、状态文本、SVG 图标、字段语义与弹窗生命周期；增加“设置与维护”页面，保留原工具快捷入口。
- 接入后端排序与页大小；增加跨页选择条、导出范围确认、资源全量占用数、空状态直接入口。
- 创建增加规范化域名校验、库存核对、提交前预览与实际成功结果；取消保留草稿，重复点击仍受幂等和禁用保护。
- 查询增加 loading/error/ready 状态、持续重试、在途请求取消与过期响应隔离；敏感锁定同时取消明文请求。
- 补齐按钮/字段键盘交互、背景 inert、弹窗焦点恢复和长表单固定操作区；修正冻结列实际宽度与偏移。
- `npm run test:ux` 加入 Windows CI，输出八个页面和多尺寸截图；以对应提交的 CI 结果为准，不能把“加入测试”当作“全部验收通过”。

仍需真实终端的 Windows DPI、原生文件选择/阅读器、使用者任务验收；历史页面仍逐步迁移，不能据此声称所有 legacy 声明或所有产品技术债已经清零。

## 验收判定

不能只凭“CSS 修改完成”宣告全 UI 通过。必须完成真实 Electron 截图审查、测试（无横向异常溢出/文本碰撞/按钮不可达）、无障碍和键盘测试，再由日常操作人员进行任务场景体验确认。

生产服务器、员工安装包和访问控制不随 UI PR 自动变更。

## 登录与注册：浅色玻璃入口（2026-10-21）

登录入口采用浅色玻璃材质，内部工作区采用相同字体与配色，并保留业务数据所需的密度。认证样式限定在 `body.auth-body` 内，由 `login.css` 维护；不再追加互相覆盖的历史修补块。

- 单一居中面板，桌面最大宽度 448px；去掉资源清单、左右分栏和重复的权限说明。
- 银白底色、静态弧面光影、半透明玻璃、细边缘高光和柔和阴影。仅面板使用背景模糊，正文与控件保持清晰；不使用持续动画。
- 优先系统字体（Apple 平台 SF / PingFang，Windows 平台 Segoe UI / 微软雅黑）；标题 30px，标签 13px，输入内容 16px，输入与主按钮高 48px。
- 登录／注册共用分段控件；方向键切换并同步焦点，Home 到登录、End 到注册。提交期间锁定模式和重复提交，保留用户填写内容。
- 首次注册仅收集用户名、密码与确认密码；显示名称沿用后端已有的用户名默认值，不额外增加一个可选步骤。
- 用户名支持中文、英文字母、数字及 `_ . -`，范围 2–32 个 Unicode 字符；扩展汉字按一个字符计数。浏览器、接口和账号管理命令复用 `username-rules.js`，不得仅放宽表单而保留服务端旧限制。密码仍至少 8 位。
- 错误紧邻字段显示，不通过整块面板抖动提示；密码可见性按钮有 44px 点击区域和清晰的状态标签。
- 注册策略继续由服务端配置决定；开放注册不展示邀请码。没有第三方登录、找回密码或管理员分配权限功能时，不展示相应入口或承诺。
- 登录／注册只有在返回真实账号且会话接口确认同一账号后才进入工作台。HTML 唤醒页和异常成功响应不能当成认证成功；注册结果不确定时保留用户名并引导登录，避免重复注册。
- 支持小屏纵向滚动、系统减少动效／透明度、高对比度与无模糊能力的回退。跨平台系统字体会有细微差异，不为外观下载专有 Apple 字体。

## 内部工作区：统一浅色材质

- 全局颜色来自 `design-tokens.css`：正文 `#242830`，次级文字 `#4b5565`，焦点蓝 `#2476c8`，主操作深灰蓝 `#303b4f`。正常、警告和危险状态保留清晰文字，不以玻璃或颜色替代语义。
- 侧栏、总览卡和内容面板采用浅银白半透明材质，边缘高光、20px 面板圆角和轻量阴影。系统字体与登录页一致，避免统计数字、标签和按钮出现多套字体。
- 表格底色固定为白色，冻结列和表头必须不透明；选中行为和悬停分别使用统一的实色令牌，水平滚动时不透出其他行文字。
- 输入框、分段筛选、下拉菜单、导入预览、备份任务、安全授权、编辑和确认弹窗共同使用语义令牌。主操作清晰，危险操作保留低饱和红色边界。
- 小于等于 700px 时，原生 popover 承载完整侧栏，支持 Escape、点击外部关闭与焦点返回；选择页面或操作前关闭导航。用户菜单、敏感显示和备份入口继续可达。
- 不把表格整体放入模糊层；限制连续动画，支持减少动效、减少透明度、高对比度和无模糊能力回退。网页多尺寸检查与真实 Windows 桌面检查分别记录，不能互相代替。

## 设置与连接：减少日常打扰

- 用户界面统一称“信用卡”，导航和页面标题统一称“设置”；不再为单一设置入口增加“工作空间”分组。信用卡仍只接受别名、末四位与有效期，禁止完整卡号和 CVV 的存储约束不变。
- 设置内容最大宽度 1000px，按“通用 / 账号与安全 / 数据管理”切换。同一时刻只展示一个分类，避免把所有说明铺成同等重要的大卡片。标签支持方向键、Home、End、选中语义及可见焦点。
- 舒适／紧凑行距使用原生单选控件，预览即时变化，不要求额外保存。偏好按账号保存在当前设备；保存失败必须区分“当前已应用”与“下次仍能保留”。
- 工作台打开时自动读取数据，操作后更新；网络恢复后自动重试。正常状态不常驻“已连接／重新连接”，手动刷新保留在通用设置和 Ctrl+R 中。
- 手动刷新显示进度并防止重复请求。成功反馈、失败时保留旧数据并提供重试；加载完成后恢复按钮本来的文字，不把“刷新数据”改成“重新连接”。
- 完整刷新保留用户当前分类、焦点和任务；用户已转向其他控件时，晚到结果不能抢回旧按钮焦点。自动连接和手动操作的完成提示分开处理。
- 数据管理首先展示加密备份和只读检查，旧版 JSON 兼容入口默认收起；替换数据的恢复动作保持明确警告与既有确认步骤。

## 资源入池与复制资料的交互约束

- 查重是录入流程的一部分。字段旁显示等待、核对中、缺项、重复、未发现重复与暂时失败；设置页的历史检查不替代实时查重。
- 输入变化后取消旧查询，不能让旧结果覆盖新内容。暂时失败保留所有输入，保存前自动重试；未确认时不能显示成功。
- 多文件独立排队，逐份校对、独立提交。默认不自动保存；自动保存需用户明确启用，仅处理字段完整且未发现重复的文件。
- 组合确认页展示实际邮箱、IP、信用卡别名和企业文件，不能只显示“自动分配 N 个”。占用资源以服务端事务校验为准。
- 详情面板明确原文、缺项与人工确认项；复制按钮必须可键盘操作。保留企业原始拼写，不把投放国家或 IP 国家写成企业注册国家。
- 320 px、390 px 与桌面宽度都要能访问文件队列、校对表单、保存操作和复制操作。
# 营业执照原件与资料校对

- 原件预览采用 File Viewer 的 Web 组件与 PDF renderer，锁定同一版本；组件在需要时加载，运行资源随程序发布。
- 桌面采用原件在左、资料在右的双栏结构；批量处理在左侧增加文件队列。原件保持可见，切换字段不重新加载文件。
- 760px 以下采用上下布局，并提供“查看资料”跳转；原件内部滚动与表单滚动分别承载阅读和校对，页面不得横向溢出。
- 使用现有浅色玻璃容器、字体、焦点和按钮规范。原件纸张保持白底，预览背景使用低对比度灰色，不给证书叠加装饰特效。
- 加载、空原件、读取错误与就绪状态必须区分；错误允许重试，不能清空字段或阻止无关的资料编辑。
- 资料字段以真实按钮提供复制，缺失字段显示“待补充”且不可复制；复制结果就地反馈。下载原 PDF 与复制企业资料使用清晰不同的文字。
- 预览只表示能查看原件，不表示 OCR、注册机关认证或查重已经完成；继续使用现有的识别和数据库校验结果。
- 切换文件、关闭弹窗或退出登录时销毁预览实例并取消读取；不得将营业执照发送到公共在线预览服务。
