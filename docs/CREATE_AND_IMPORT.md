# 创建与资源导入模块

真实页面继续由现有原生界面承载，业务规则与异步任务按职责迁移。`app.js` 保留创建核对、结果呈现和业务入口；不把后端鉴权、幂等事务或资源分配移到前端。

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `record-create.js` / `parseStart`、`draft` | 指纹起始解析、域名规范化、重复/500 条/编号/资源库存校验，生成独立请求体 | 表单、选择 ID、资源总数与可用数、当天日期与下个编号，均显式传入 |
| `record-create.js` / `createSubmitter` | 提交快照、同步阻止重复确认、当前会话内的幂等重试 | 请求函数、SHA-256 和随机键；不访问 DOM 或账号全局状态 |
| `resource-import.js` / `createPreview` | 防抖、文本解析、文件读取、取消、关闭和结果所有权 | 显式文本读写、请求、活动状态、反馈回调、弹窗 signal |
| `resource-import.js` / `create` | 普通/智能导入弹窗、预览、错误重试及确认写入 | 现有 API、共享 UI、弹窗入口、资源格式、保存后同步等显式适配器 |

## 创建与重试

域名去除网址前缀与路径、转小写后检查重复；保持现有空资源库可创建不关联记录的行为，库存不足仍提示补充。显示预览和最终提交使用同一组纯规则；服务端继续进行最终验证与事务分配。

确认时复制请求体，异步摘要和网络等待期间的原表单修改不能改变已核对的提交。重试缓存只包含完整请求的 SHA-256 摘要和幂等键，移除 `state.submission` 中的完整序列化文本；不把身份证等内容放入长期重试状态或浏览器存储。相同内容的失败重试沿用键，成功后释放，下次独立创建使用新键。刷新页面后不承诺保留重试键。

摘要准备期间弹窗被关闭或锁定，尚未发送的请求不再启动。已发出的写入继续按服务端结果同步，不承诺撤销；旧确认入口不能替换新弹窗或清空新草稿。重试时先清除旧错误，失败保留原核对内容。

## 导入生命周期

每次输入、换文件或重试立即作废旧任务，并清空可提交的旧候选。文件读取和解析共用修订号，即使文件回调忽略取消、手工输入后又恢复相同文字，旧结果或旧错误也不能覆盖新候选。关闭/替换/锁定弹窗会取消防抖、请求和读取，关闭后不再发出待执行的解析。

中文组词期间等待确认，结束后合并最终 input；文件预算保持 10 MiB。读文件、识别、空内容与失败分别显示；解析失败保持原文，停用确认并提供“重试识别”。读文件失败要求重选，清空原生文件选择值以支持再次选择同一文件。成功预览只显示“密码已识别”等摘要，不直接展示密码或 2FA 内容。

确认导入仍使用共享 pending 状态，阻止重复写入和普通关闭。确认前固定请求与数量摘要；即使锁定清空了预览候选，已发送导入的结果仍能准确反馈。解析/文件错误只属于原弹窗，不能落入后来打开的任务。

## 设计与验证

导入格式说明、预览、分组与错误状态统一归入 components 层，移除 legacy 中重复规则。正文与预览使用 13px 令牌，长资源字段可换行，错误有持续文字与重试按钮，放大后仍可到达确认区。

纯模块测试覆盖草稿边界、提交快照、幂等重试、关闭取消、旧解析/文件错误、改写再恢复文字和超限文件；生产脚本回归检查失败创建锁定后不残留序列化私密草稿。Windows UX 使用真实 API 验证“第一次确已写入但响应丢失，再用同键重试只创建一次”，以及解析失败重试、关窗前防抖、旧文件错误、125%/150% 导入布局。合成回调/软件缩放不替代实体输入法、系统文件对话框和实际 DPI 验收。

后续仍需迁移创建核对视图与其他业务视图，进一步拆分主文件；本轮未改变生产环境或自动修复历史数据。
