# 工作台回归与改进记录

## PDF 问题的实际复现

旧分支基线 `19298f2` 的 PDF 接口把提取原文直接传给「一行一个公司名」解析器。用本次用户上传的丹麦注册证书复现：旧解析得到 **14 条**，改进后的 PDF 识别只得到 **1 条**。附件没有加入源码、发布包或默认数据库。

PDF 导入保持「识别 → 校对 → 确认保存」三步。未识别时手动补充字段，不能把页眉、地址和页脚变成新公司。原件内容哈希和已有公司名称共同确定更新目标；同一 PDF 校对名称后再次导入保留原记录的编号及占用状态，冲突时拒绝合并。

## 本轮修复

| 流程 | 修复及优化 |
| --- | --- |
| 营业执照 | 明确一个文件一条记录；移除旧批量 PDF 界面；重复文件更新原记录；取消不保存；空/无效附件拒绝；清理当前快照中不再引用的 PDF |
| 资源与记录 | 修改资源同步当前关联记录；编辑不能制造重复资源；严格检查编号与创建数量；域名忽略大小写去重；已占用/停用资源不可误选 |
| 导入 | 阻止过期预览覆盖新输入；阻止重复确认；TXT 文件大小限制；带 `user:` 的代理凭据不再误判为邮箱 |
| 列表与交互 | 每页 50 条；搜索覆盖全部数据；跨页选中保留；只全选当前页；无结果提示；搜索后保留列布局；导出范围明确；弹窗键盘焦点管理 |
| 导出与敏感字段 | CSV 公式保护与长数字文本前缀；AdsPower 字段换行清理；敏感信息隐藏时阻止复制完整代理凭据 |
| 备份恢复 | 验证资源关联、独占占用、重复指纹与附件存在性；修正错误的可用状态；无效恢复不覆盖当前数据 |

## 验证证据

- `npm test`：25 项 API/存储测试通过，0 失败、0 跳过。
- `DISPLAY=:99 npm run test:desktop`：12 个界面流程通过；覆盖 51 条记录/资源分页、TXT 混合导入和带文本层的 PDF。
- 传入本次用户的真实 PDF 再运行桌面回归：相同 12 个流程通过；识别组织、地址、保留原字节，重复校对导入只保留一条。
- 历史解析器与当前接口使用同一证书原文对比，确认 14 → 1。
- 语法检查和 `git diff --check` 通过。

测试使用临时目录。默认 PDF 为程序生成的测试证书；用户提供的 PDF 不作为仓库测试文件。原生文件选择框和默认 PDF 阅读器调用在自动测试中被替代；真实 Windows 安装、系统阅读器和卸载验收仍未执行。本轮只修改、启动及检验云端项目，没有在用户电脑安装程序，也没有重新生成 Windows 启动包。

旧版已经错误保存的逐行记录不能安全地自动删除：单靠公司名称无法区分误导入内容和真实公司。应先备份、核对这些条目及关联记录，再决定清理。
