# 记录关联检查与核对修复

入口：设置与维护 → 数据一致性 → 检查本人数据。检查本身只读；不会替用户决定历史记录应该归属哪一份资源。

## 检查范围

| 情况 | 解释与处理 |
| --- | --- |
| 记录快照与关联资源不同 | 展示字段差异，凭据只提示“值不同”；核对后可明确选择以当前关联资源覆盖快照，或打开记录重新选择资源 |
| 有快照、无关联 | 可能是历史独立录入，列为人工核对，不能自动认定错误或按名称关联 |
| 关联在本人资源库中不可用 | 不查询/展示其他成员资料，打开记录重新选择或清空 |
| 邮箱、付款工具或执照被多条记录使用 | 展示本人范围的占用数，人工决定各条记录的分配；代理允许共享 |
| 已有关联但资源标记未使用 | 核对后可明确修正为已使用；不自动清空、释放或覆盖停用状态 |

手工标为已使用但没有记录引用的资源，可能是在预留，不作为自动释放候选。

## 数据与权限契约

- `GET /api/data-integrity` 按登录会话确定 owner，拒绝客户端 owner 参数，不需要显示凭据的授权。内部仅为比较使用所需凭据，不返回原文、密文或 PDF。
- 按 id 游标，每批最多 100 条。第一次获取当前最大记录 id，后续沿用上限；新增记录通过“重新检查”纳入。检查不是冻结数据库的全局快照，编辑或删除仍可能发生。
- 结果明确为“本批”，不把第一页没有问题当作本人全部数据无问题。关闭弹窗会中止在途查询，旧响应不能填入新弹窗。
- `POST /api/data-integrity/repair` 要求临时解锁、合法 action/prefix、当前记录/资源编号与两个版本。重新检查已有真实关联，不接受新归属、任意字段或 owner；不按邮箱/名称/公司名猜测身份。
- 同步快照只更新所选类型的字段，不变更关联编号；改为已使用只更新该资源状态。缺失资源、版本变化、关联变化或状态不适用时拒绝写入。
- 写入与不含凭据的 `records.integrity.repair` 审计在同一事务中提交。失败整体回滚。重复旧提交由版本保护拒绝，不重复修改。
- UI 展示影响范围与前后差异、要求勾选确认；提交中使用公共 pending，失败保留原因。过期结果须返回检查，不继续提交旧版本。结果完成后重新检查该批。

## 模块边界

- `lib/resource-snapshots.js` 是四类资源快照字段的共享映射，正常编辑、资源同步与检查共用，避免检查与业务规则各写一份。
- `lib/record-integrity.js` 管理有界检查和修复，`server.js` 仅接入鉴权、参数与事务。
- `public/record-integrity.js` 独立管理检查、分页、差异核对与修复生命周期；主渲染只暴露入口，使用既有公共组件、设计令牌与弹窗。

## 验证与边界

HTTP 回归覆盖四类差异、加密等值比较、只读性、凭据不外泄、个人隔离、缺失/独立/重复情况、代理共享、双版本冲突、旧提交拒绝、审计失败回滚和有界游标。真实 Electron 回归覆盖入口、批次、差异、人工路径、授权/确认、取消、版本变化与重新检查。

这提供了历史问题的核对工具，不代表生产历史数据已经检查或修复。没有自动全量改写，未合并或部署生产。大规模个人备份任务、后续业务控制器拆分与真实终端 DPI/日常任务验收仍独立推进。
