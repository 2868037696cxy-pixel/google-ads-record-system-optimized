# 个人加密备份任务（v3）

入口：设置与维护 → 管理备份任务。本功能只备份和恢复当前账号的记录、四类资源及被营业执照引用的 PDF。原有 v2 JSON 导出和恢复保持兼容，继续执行 64 MiB 预算；v3 不经过旧 JSON 恢复入口。

## 用户流程与边界

1. 授权后建立备份任务，后台生成一致快照。关闭界面仍继续打包；退出服务时正在打包的任务标记失败，可重新建立。
2. 就绪后下载 `.awbp`，界面提供整个文件的 SHA-256。确认本机文件已保存再删除服务器临时任务。
3. 恢复时选择 `.awbp`，授权建立上传任务。按 1 MiB 分块上传，服务端验证每块 SHA-256 并返回已确认位置。
4. 可暂停、关窗或断线，之后从任务列表选择同一个文件续传。服务器重启后保留已确认位置，截去未提交的文件尾部；不会把发出请求当作上传成功。
5. 上传完整后，另行授权执行加密完整性、原账号与密钥、字段、资源关联及 PDF 内容校验。校验失败不进入恢复。
6. 核对服务端验证的备份数量与当前数量，勾选明确覆盖确认后提交。当前数据变化会返回冲突，必须重新核对并重新勾选。

| 限制 | 当前实现 |
| --- | --- |
| 单个加密文件 | 最大 512 MiB |
| 每张资源表 / 记录表 | 最多 100,000 行 |
| 单份 PDF | 保持现有 10 MiB 限制 |
| 临时保留 | 创建后 24 小时，按分钟清理；到期任务不可访问 |
| 同时持有 | 每账号最多 2 个占用空间的任务 |
| 临时空间预留 | 每账号 2 GiB，全服务 8 GiB，并检查可用磁盘空间；实际删除临时文件后才释放额度 |
| 创建频率 | 每账号每小时最多 20 次，删除任务不能重置计数 |
| 打包 / 校验 | 全服务同时最多 2 个工作线程，10 分钟上限；每个线程堆限制 256 MiB |
| 下载 | 流式响应、SHA-256 ETag、单段 HTTP Range；具体下载续传能力由浏览器 / 桌面下载器决定 |
| 上传续传 | 界面显式暂停、重选同一文件、从服务器确认的位置继续 |

文件依赖**原服务器密钥和原账号**。备份不携带密钥，也不恢复账号密码或登录会话。迁移到另一台服务器需要单独的原密钥与账号身份迁移流程；不能把此功能当作跨服务器或跨账号导入。部署维护的全库流式加密备份继续独立使用。

客户端在内存中只保留当前分块和用于识别原文件的有限采样。采样摘要不是安全认证；完整文件的 AES-GCM 认证才决定能否进入核对。浏览器没有将大文件转为 JSON、Base64 或完整 Blob 下载。

## 代码结构与状态

| 层 | 实现 |
| --- | --- |
| 独立交互控制器 | `public/backup-tasks.js`，共享按钮、令牌、弹窗与取消信号 |
| HTTP 与鉴权 | `server.js`，继续复用本人会话、来源头与敏感授权 |
| 持久任务与配额 | `lib/personal-backup-jobs.js`，任务按 owner_id + UUID 定位 |
| 文件构建、验证与恢复映射 | `lib/personal-package.js` |
| 工作线程 | `lib/personal-backup-worker.js` |
| 流式加密 | `lib/vault.js`，复用现有密钥，认证完整外层头部 |

导出状态：`building → ready`，失败进入 `failed`。恢复状态：`uploading → checking → review → complete`。暂停不改变服务器的 `uploading` 状态。校验过程被服务重启打断后返回上传状态，可重新发起完整校验。已完成恢复重试返回同一完成结果，不重复写入或记恢复审计。

备份先在私有任务目录建立一份全新的个人 SQLite 文件，只写入本人业务行、引用原件及占位用户。没有从全库文件复制再删除别人的行，因此不会带走 SQLite 空闲页中的其他账号数据。凭据字段和 PDF 仍使用原有内层加密；整个文件再流式 AES-256-GCM 加密。

上传暂存加密原包；验证时解密到私有暂存数据库。目录使用 0700、文件使用 0600（Windows 仍需按部署账号管理 ACL）。密钥不在任务 HTTP 数据中。任务错误不返回异常堆栈、文件路径或凭据原文。

恢复前验证暂存文件全量摘要；事务内再次比较本人记录和资源的 ID/版本及执照附件信息。预检跨账号全局执照判重和 PDF 登记，再仅替换本人的记录、资源与无引用原件，重新映射关联 ID。写入、任务完成标记和审计在同一事务；冲突或审计失败全部回滚。其他账号的记录和无引用 PDF 均不清理。

授权过期后重新核对会清空覆盖确认；锁定或关闭后的旧响应不能重新打开核对弹窗。上传暂停只承诺停止后续分块，不承诺撤销服务器已经收到并确认的分块。恢复提交结果不明时先查任务状态，不能直接重复建立恢复任务。

## 验证

- `tests/personal-package.test.js`：本人包不含其他账号/会话/审计/密码原文、精确 PDF 往返、关联 ID 重映射、恢复幂等；分块重放、错哈希/错位置、HTTP Range、账号隔离、密文篡改、旧版本与附件冲突、事务审计故障回滚、过期/配额/来源保护、跨账号判重与删除任务后的频率限制。
- 通过真实 HTTP 上传 5 份各约 8 MiB 的有效合成 PDF：旧 JSON 导出明确拒绝，新任务分块往返后逐份比对 SHA-256。
- `tests/personal-package-resume.test.js`：独立服务子进程重启，保留可下载包，截断未确认尾部，从已确认位置继续上传并完成验证恢复。
- `npm run test:backup-ui`：本机开发版 Electron 与打包客户端的隔离 HTTPS 服务两种运行方式，原生 `.awbp` 保存、完整文件哈希、分块已保存但响应丢失后的暂停对账、重选/错文件/续传、验证后范围对照、未勾选不可提交、数据变更拒绝、重新核对、一次恢复审计、锁定后迟到响应、125%/150% 软件缩放。

以上使用临时账号、临时数据库与合成 PDF；不访问生产数据。512 MiB 和每表十万行是实现边界，不能用 40 MiB 往返测试声称所有极限与任意规模都已压测。真实 Windows DPI、系统文件对话框、安装器操作和长期业务使用仍需人工验收。

打包客户端保持既有远程模式约束，不能用开发版的本机环境变量覆盖。CI 仅复制安装候选到临时目录，将副本的连接配置指向临时 HTTPS 服务；在一次性 Windows runner 的当前用户证书库导入该服务的临时证书，结束后移除。原安装候选的 ASAR 前后哈希必须一致，产品不增加证书信任或本机回退。
