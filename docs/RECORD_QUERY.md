# 记录查询控制器

`public/record-query.js` 负责请求所有权、防抖、取消、分页纠正和查询错误。通过 `WorkbenchRecordQuery.create()` 创建实例；不读取 DOM、账号存储或全局业务状态，不缓存旧结果，也不管理跨页选择。

## 职责与接口

| 接口 | 契约 |
| --- | --- |
| `readQuery()` | 读取页码、页容量、排序、关键词、状态、是否显示凭据及敏感锁定代次 |
| `request(path, { signal })` | 调用现有 API，共享取消与 60 秒超时；账号鉴权仍由服务端负责 |
| `onResult({ items, total, page })` | 只发布当前查询完整有效的结果；调用方更新记录与页码，保留跨页选择 |
| `onPhase(phase, error, reason)` | 更新 ready / loading / error；loading 区分防抖、组词和实际请求 |
| `onRender(mode)` | 调用方选择局部或整页渲染；控制器不拼接 HTML |
| `onError(error)` | 仅报告防抖任务的当前失败；主动查询的错误仍向调用方抛出 |
| `load(options)` | 立即查询；成功发布返回 true，失去所有权返回 false，当前失败抛出错误 |
| `schedule(options)` | 立即作废旧请求，再等待 250ms；连续输入只发最后一次 |
| `invalidate({ reason })` | 取消防抖与在途请求；锁定和中文组词均使用此入口 |

`app.js` 提供显式适配器，保留 `loadRecordsPage` / `invalidateRecordQuery` 入口供安全锁定、关联核对和现有业务调用。DOM、焦点、选择与导出范围仍由界面层负责。

## 异步与分页

每次查询捕获不可变参数快照。发布前检查请求代次、取消状态、完整参数和敏感锁定代次；即使底层请求忽略取消，旧成功与旧失败也不能覆盖新任务。关键词先去除两端空白；分页、排序、状态与显示凭据继续由服务端验证。

并发删除使当前页超出范围时，在同一个所有权和超时预算内读取最后一页。纠正完成前不发布中间空页，不提前改写调用方页码。纠正请求也可被后来输入或锁定取消。失败保留旧数据与持续重试入口，旧表格暂时 inert。

## 输入与键盘

中文 compositionstart 立即作废旧查询；组词中的 input 不发请求。compositionend 与最终 input 合并为一次防抖，确认文字后才查询。以实际输入节点的 WeakSet 兼容缺少 isComposing 的事件，不保留全局组词标志。组词时显示“确认输入后自动查询”，不显示网络加载转圈。

局部渲染保留当前输入焦点、选区和表格滚动，不保存输入副本。翻页保留原方向的可用按钮；到边界时回到可用分页入口。等待期间用户已移动焦点、切页或打开弹窗时不强行聚焦分页。每页数量重建时恢复当前焦点，不把稍早操作的焦点抢回。

## 验证与边界

`tests/record-query.test.js` 使用实际控制器和受控请求，覆盖旧成功/失败、防抖取消、重试、分页纠正及其取消、全部参数/锁定代次和无效总数。`tests/workbench-lifecycle.test.js` 执行生产脚本与实际事件处理，复现组词时旧请求晚到。`test:ux` 在真实 Electron 中验证事件序列、请求次数、焦点、筛选按下尺寸和截图，并保留已有跨页选择、导出、锁定与布局回归。

合成 CompositionEvent 验证应用事件处理，不代替 Windows 实体输入法与屏幕阅读器验收。创建规则/提交与资源导入已另行迁移，见 `CREATE_AND_IMPORT.md`；创建核对视图、其他业务视图和剩余 legacy 样式仍需后续分批处理。
