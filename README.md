# 账号工作台 1.2

Windows 桌面程序 + 中央后台。每人只看自己的记录，所有成员上传的 PDF 在服务端统一查重。

正式 Windows 安装包已预置 `https://ads.fbsoso.xin`。员工不需要设置环境变量、安装额外组网软件或配置本地数据库。必须先升级后台，再分发客户端。

**部署与运维：[1.2 版本说明](docs/RELEASE_1_2.md)**。请核对对应提交的 GitHub Actions 结果，不将尚未通过测试的分支当成已经上线。

## 功能

- 运营总览、资源库存、账号记录、搜索分页及分类筛选记忆。
- 邮箱、代理、付款工具引用、营业执照导入与批量创建。
- 个人数据隔离；普通用户无法查看全员资料报表。
- 全员 PDF 内容指纹查重；改名、并发提交以及删除后重新导入均受控。
- 邮箱密码、2FA、代理密码、身份字段和 PDF 原件加密保存。短时显示和敏感导出需要重新验证登录密码。
- 不接收或保存 CVV/CVC 和完整支付卡号，使用付款工具别名、末四位及有效期。
- 普通 CSV 不含密码；AdsPower 凭据导出需要显式授权；个人备份及服务器快照均加密。
- 防重复提交、版本冲突提示、会话撤销、个人安全操作记录。
- 桌面断线重连页，不会退回各自的本地数据库。

## 开发与测试

Node.js 22.16+（已部署环境为 22.22.2）或 24。

```bash
npm ci
npm test
npm run test:desktop
npm run test:desktop:remote
npm run build:win
```

只有未打包的开发进程设置 `ADS_WORKBENCH_MODE=local` 才会启用隔离的本机测试模式。正式安装包始终使用预置的 HTTPS 后台地址。

## 服务器升级

在经核验的版本目录执行：

```bash
sudo bash scripts/deploy-ubuntu.sh
```

脚本识别实际 Node 路径，先测试再更新，保留原加密密钥，创建并验证加密快照；升级失败尝试回滚。仅重启 adsworkbench，不修改 cloudflared、Hermes、OpenCraft、VNC、SSH、DNS 或防火墙。

后台继续使用单机 SQLite，无需安装 PostgreSQL。所有 PDF 原件是同一中央数据库中的加密 BLOB，不是员工电脑各存一份。数据库普通业务元数据仍可由服务器运维读取；加密不等于抵御已掌握服务器及密钥的攻击者。

## 发布边界

GitHub CI 不会直接部署到实际云服务器。管理员需要执行升级，并设置独立的异地备份目的地。当前 Windows 安装包没有商业代码签名证书，应校验哈希并遵循组织的软件审核流程；不要关闭系统保护来运行来源不明的文件。

不要将密码、Tunnel Token、生产加密密钥提交到 GitHub 或聊天。每个版本的测试范围、备份恢复和账号管理方法见版本说明。
