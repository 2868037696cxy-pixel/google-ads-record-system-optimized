# 账号工作台 · Ads Operations Console

广告账号资源工作台：把谷歌邮箱、代理、信用卡、营业执照资料库和广告账号记录归档在同一处，供团队检索、分配、导出与交接。

本版本已从「单机桌面应用」升级为**服务器版多用户系统**：大家访问同一个网址，各有账号密码，数据存在同一个 SQLite 库里。

- 每人只看到自己的资源与记录（邮箱 / 代理 / 信用卡 / 营业执照 / 记录全部按账号隔离）
- 营业执照**跨全体成员判重**：同一家公司只能被一个人导入，重复导入会被拒绝并说明是谁在什么时候导入的
- 仍然可以打包成 Windows 桌面应用（Electron），单机使用时自动使用本机账号，无需登录

## 快速开始（服务器版）

需要 Node.js 22.13+（推荐 24 LTS，`node:sqlite` 依赖它）。运行期只有 3 个依赖，无需数据库服务。

```powershell
npm ci
npm start
```

默认监听 `127.0.0.1:3000`。让同事访问需要绑定对外地址：

```powershell
$env:HOST='0.0.0.0'; $env:PORT='3000'; $env:SESSION_SECURE='1'; npm start
```

首次访问会跳到登录页，点「注册」创建第一个账号即可开始使用。

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 监听地址；对外提供服务用 `0.0.0.0` |
| `PORT` | `3000` | 监听端口 |
| `DATA_DIR` | `./data` | 数据目录 |
| `DB_FILE` | `<DATA_DIR>/workbench.sqlite` | SQLite 数据库文件 |
| `DATA_FILE` | `./data.json` | 旧版单机数据文件；存在时会在第一个账号创建时自动迁移 |
| `REGISTRATION` | `open` | 注册策略：`open` 任何人可注册 / `invite` 需要邀请码 / `closed` 关闭注册 |
| `INVITE_CODE` | 空 | `REGISTRATION=invite` 时的邀请码 |
| `SESSION_SECURE` | 空 | 设为 `1` 时会话 Cookie 只走 HTTPS（**部署在 HTTPS 后面必须打开**） |
| `DEDUP_ADDRESS_MODE` | `reject` | 地址判重强度：`reject` 拒绝 / `warn` 只提示 / `off` 不判地址 |
| `LOG_LEVEL` | `info` | 设为 `silent` 关闭日志 |

### 部署提示

- **放在 HTTPS 反向代理后面**，并设置 `SESSION_SECURE=1`。反代需要传递 `X-Forwarded-*`，服务已开启 `trustProxy`。
- 反向代理的请求体上限要 ≥ 64 MB，否则恢复含原件的备份会失败。
- 备份直接复制整个 `DATA_DIR` 即可（SQLite 使用 WAL，复制前先停服，或用 SQLite 的在线备份命令）。

### 账号与权限

没有管理员角色。每个人的资源池和记录都归自己，互相看不到，也不能通过编号访问他人的数据。

跨账号的规则只有两条：

1. **营业执照判重是全局的**：组织名称、法定名称、CVR 注册号、街道地址任一命中即视为重复。谁先导入谁占住；别人再导入会被拒绝，并提示归属。同一账号重复导入自己已有的公司属于**更新**，不会报错。
2. **营业执照原件的 SHA-256 是全局主键**：同一份 PDF 不会存两份；附件清理也是全局判断，不会误删别人的文件。

> ⚠️ 隐私权衡：`REGISTRATION=open` 加上「已被谁导入」的提示，意味着任何注册者都可以通过试探公司信息，推断出团队在运营哪些公司以及归属谁。如果这不可接受，请改成 `REGISTRATION=invite`（配 `INVITE_CODE`）或 `closed`，并只给团队成员开账号。

### 修改判重口径

- 地址判重偏严（同一地址多家公司很常见）：设 `DEDUP_ADDRESS_MODE=warn` 改为只提示不拦截。
- 公司名后缀（`ApS`/`A/S`/`IVS`/`Ltd`/`GmbH` …）、大小写、空格、标点、全角字符、丹麦语字母 `æ ø å` 在比对前都会被归一化。
- 侧栏「全体重复体检」可以扫描**全体成员**的营业执照，列出任何形式的重复（包括同一份原件被多条资料引用）。

## 各功能区

### 工作台

- 填写国家、产品、域名（一行一个）批量创建记录，指纹名称按「日期 + ads + 序号」自动生成，序号按账号各自计数。
- 邮箱、信用卡、营业执照按顺序自动分配并标记为「已使用」；代理可选「共享一个」「自动分配」「不填」。
- 记录与资源列表每页 50 条，搜索覆盖全部数据；勾选跨页保留，「全选」只作用于当前页。
- 导入预览只接受最新一次识别结果，识别与保存期间禁止重复提交；弹窗支持 Escape 关闭、Tab 循环、关闭后焦点返回原控件。

### 资源库

- 已占用的独占资源不能被重复选择，也不能删除或标记为「未使用」。
- 解除关联后自动释放；共享代理要等引用它的**最后一条**记录被删除才释放。
- 修改资源时会校验重复，并同步刷新关联记录的导出快照。

### 营业执照与原 PDF

1. 「营业执照」→「导入营业执照」，选择 PDF（最大 10 MB / 50 页）。一个文件对应一条资料，多页证书也只保存一条。
2. 自动识别丹麦 Business Authority 注册证书；扫描件没有文本层时需要手动填写（本版本未集成 OCR）。
3. 校对组织名称、法定名称、街道地址、门牌号、邮编、城市与 CVR 注册号后「确认保存」。**只有确认保存才会存原件**，关闭弹窗不会留下临时文件。
4. 识别阶段就会预警重复；确认导入时若被判重，表单上方会列出「哪家公司、依据哪个字段、被谁在什么时候导入」，导入被拒绝，不会覆盖任何人的数据。
5. 同一份 PDF 重新导入并修正元数据 → 更新原记录并保留编号与分配状态。

### 导出

- **CSV**：给公式内容（`=` `+` `-` `@` 开头）、超长数字、零开头的数字加文本前缀，防止表格软件执行公式或改写卡号 / CVV。该前缀用于表格阅读，机器再导入时需自行处理。
- **AdsPower TXT**：清除字段内换行，避免插入额外配置行。

### 备份与恢复

- 网页版：侧栏「导出备份」下载**本人**的资源、记录与原件（JSON）；「恢复备份」只覆盖本人数据，不影响其他成员。
- 恢复前会完整校验备份（资源关联、独占占用、指纹、PDF 的 SHA-256）；**校验失败时现有数据一个字节都不会动**。
- 桌面版：侧栏「备份 / 恢复 / 数据目录」使用原生文件对话框。
- 数据文件损坏时不会用空库覆盖原文件：桌面版会把 `workbench.sqlite` 改名保留后重建，再从界面恢复备份。

### 从旧版单机数据迁移

把旧的 `data.json` 放到 `DATA_FILE` 指向的位置（默认仓库根目录），启动后**第一个注册的账号会自动接管全部旧数据**，随后文件被改名为 `data.json.migrated`，避免重复导入。桌面版由本机账号自动接管。

## 开发

```powershell
npm test              # 服务端回归（账号、隔离、判重、备份、资源生命周期…）
npm run desktop       # 以 Electron 桌面应用方式运行
npm run build:win     # 构建 Windows 安装版与 ZIP 版，输出在 dist
```

### 代码结构

| 文件 | 职责 |
| --- | --- |
| `server.js` | HTTP 路由 + 各类文本/PDF 解析器（解析器与旧版逐字一致） |
| `lib/db.js` | SQLite 建库、表结构与事务（`node:sqlite`，无原生依赖） |
| `lib/auth.js` | scrypt 密码、会话与 Cookie、登录限速 |
| `lib/store.js` | **所有数据访问的唯一收口点**，每条查询都带 `owner_id` |
| `lib/dedup.js` | 营业执照归一化与跨用户全局判重、重复体检 |
| `lib/storage.js` | 备份快照校验 |
| `public/` | 前端（登录页 `login.*`，主应用 `app.js` / `licenses.js` / `styles.css`） |
| `desktop/` | Electron 外壳：本机免登录、原生备份/恢复、窗口状态 |

新增数据访问请一律走 `lib/store.js` 并带上 `owner_id`——这是数据隔离不被破坏的前提。

## 已知限制

- 没有管理员角色，也没有跨账号的资源共享——这是刻意的设计，按需求「各人数据互不可见」实现。
- PDF 判重依据的是提取出的字段，扫描件无法自动识别时只能手工填写，此时判重依赖人工填写的准确性。
- 备份以 JSON 内嵌 base64 保存原件，附件很多时文件会比较大（单次恢复上限 64 MB）；不适合当海量文档归档。
- 会话有效期 30 天并滑动续期，服务端可随时清理（`sessions` 表）。
